# Сервера VLESS + Reality с 3x-ui

Один файл `setup-vpn.sh` запускается отдельно на каждом сервере. Он устанавливает 3x-ui, создаёт входящее подключение VLESS + TCP/RAW + Reality, настраивает HTTPS панели и подписочного сервиса по IP. Пользователей скрипт не создаёт. При создании клиента в панели выбирайте Flow `xtls-rprx-vision`.

Скрипт рассчитан на новые VPS с Ubuntu 22.04 или 24.04, systemd, архитектурой amd64/arm64 и публичным IPv4. Собственный домен и управление DNS-записями не нужны. Обычное разрешение имён на сервере должно работать: оно требуется для скачивания пакетов и доступа к TLS-сайту Reality.

Версии зафиксированы: **3x-ui v3.8.5**, **acme.sh 3.1.6**. Скачиваемые архивы и служебные файлы проверяются по SHA256, записанным в скрипте. Используются SQLite и установка непосредственно на сервер, без Docker и PostgreSQL.

## Статус проверки

Проверены синтаксис Bash, ShellCheck и офлайн-тесты входных данных, JSON-запросов и сохранения ключей при повторном выполнении. Форматы CLI/API сверены с исходниками 3x-ui v3.8.5.

**Полная установка на Ubuntu, выдача настоящего сертификата и подключение через HAPP в этой среде не проверены.** Перед публикацией инструкции испытайте скрипт на первом пустом VPS, затем повторите на втором. Встроенные проверки установщика выполнятся уже на ваших серверах; они не заменяют проверку подключения с телефона или компьютера.

## 1. Откройте порты в личном кабинете хостинга

Если у провайдера есть внешний firewall/security group, разрешите входящий TCP:

| Порт по умолчанию | Назначение |
|---|---|
| Ваш действующий SSH-порт, обычно 22 | Подключение к серверу |
| 80 | Выдача и последующее продление сертификата по IP |
| 443 | VLESS + Reality |
| 2053 | HTTPS-панель 3x-ui |
| 2096 | HTTPS-подписки |

443, 2053 и 2096 можно заменить в мастере установки. Внешний firewall должен разрешать именно выбранные порты. Порт 80 требуется постоянно для будущего продления сертификата; никакой постоянный сайт на нём не устанавливается.

Скрипт сам устанавливает UFW, разрешает SSH и перечисленные сервисы. Настройки SSH, пароль root и метод входа он не меняет. VPN работает на TCP, в том числе передаёт поддерживаемый клиентом UDP-трафик внутри соединения; открывать UDP 443 для этого профиля не требуется.

## 2. Загрузите файл на первый сервер

Сохраните `setup-vpn.sh` на свой компьютер. В PowerShell или терминале компьютера выполните, подставив путь к файлу и IP сервера:

```powershell
scp "C:\Users\ВАШЕ_ИМЯ\Downloads\setup-vpn.sh" root@IP_ПЕРВОГО_СЕРВЕРА:/root/setup-vpn.sh
ssh root@IP_ПЕРВОГО_СЕРВЕРА
```

При нестандартном SSH-порте, например 2222:

```powershell
scp -P 2222 "C:\Users\ВАШЕ_ИМЯ\Downloads\setup-vpn.sh" root@IP_ПЕРВОГО_СЕРВЕРА:/root/setup-vpn.sh
ssh -p 2222 root@IP_ПЕРВОГО_СЕРВЕРА
```

Ключ SSH при необходимости указывается обычным параметром `-i`. Эти команды не требуют сообщать кому-либо пароль или приватный ключ.

## 3. Запустите установку на сервере

Следующие команды выполняются **в SSH-сеансе на Ubuntu**:

```bash
cd /root
sed -i 's/\r$//' setup-vpn.sh
bash setup-vpn.sh
```

`sed` убирает Windows-переносы строк, если редактор их изменил. Оригинальный файл уже сохранён с LF.

Мастер спросит:

1. Название сервера — например `Germany`.
2. Публичный IPv4 этого сервера — обычно определяется из SSH-сеанса, его нужно проверить.
3. Действующий SSH-порт — он будет сохранён, а не изменён.
4. Порты VPN, панели и подписок — обычно достаточно нажать Enter.
5. Внешний TLS-сайт для Reality — по умолчанию `www.microsoft.com`.

Target/SNI — это имя внешнего сайта, который используется Reality; владеть этим доменом не нужно. Скрипт проверяет сертификат сайта, TLS 1.3 и HTTP/2 с вашего VPS. Если проверка не проходит, предложит ввести другой сайт. Такая проверка не гарантирует доступность VPN у конкретного оператора связи.

Скрипт не проводит обновление всей ОС и не перезагружает VPS. Он устанавливает нужные пакеты, скачивает проверенные файлы, создаёт случайные учётные данные и ключи. Выдача сертификата может занять несколько минут.

В конце появятся адрес панели, логин и пароль. Данные сохраняются на сервере в файле, доступном только root:

```bash
cat /etc/vpn-bootstrap/access.txt
```

Адрес панели будет примерно таким:

```text
https://IP_СЕРВЕРА:2053/СЛУЧАЙНЫЙ_ПУТЬ/
```

Путь обязателен, включая завершающий `/`. При успешной выдаче сертификата браузер должен доверять HTTPS без отключения проверки сертификата.

## 4. Повторите на втором сервере

Передайте тот же файл на второй VPS и выполните те же команды. Укажите другое название — например `Netherlands`.

Порты на разных серверах могут совпадать. Пароли панели, ключи Reality, Short ID и пути генерируются независимо. Копировать базу данных первого сервера на второй не нужно.

## 5. Создайте пользователей в панели

После установки входящее подключение уже существует, но список клиентов пуст. Для каждого человека:

1. Создайте клиента в подготовленном входящем подключении на первом сервере.
2. Укажите Flow **`xtls-rprx-vision`**, включите клиента и задайте имя, например `ivan`.
3. Создайте отдельного клиента на втором сервере с тем же понятным именем. UUID может быть другим.
4. Сначала проверьте каждый сервер отдельной `vless://`-ссылкой в HAPP.
5. Для объединения скопируйте `vless://` клиента со второго сервера и добавьте её в дополнительные/внешние ссылки соответствующего клиента на первом сервере.
6. Скопируйте **ссылку подписки первого сервера** из карточки клиента и импортируйте её в HAPP. В подписке должны появиться два сервера.

Пользователю достаточно одной ссылки. Для другого человека создайте свою пару клиентов и свою подписку. Общая подписка не синхронизирует лимиты, пароли или блокировку между независимыми панелями: отключая пользователя, отключайте его на обоих серверах.

Если изменили параметры второго сервера, замените его дополнительную ссылку в первой панели и обновите подписку в HAPP. Одинаковый UUID/Sub ID на двух панелях сам по себе подписки не объединяет.

Адрес «Основа подписки», который напечатал установщик, **не является готовой пользовательской подпиской** — нужный полный адрес выдаёт панель после создания клиента.

Сама подписка находится на первом сервере: при его недоступности обновление подписки временно не работает. Уже загруженное подключение ко второму серверу остаётся отдельным. Автоматическое переключение между серверами скрипт не настраивает.

## Повторный запуск и ошибки

После успешной установки повторный запуск проверяет службы и сертификат, но не переустанавливает панель и не меняет пароли, ключи или пользователей:

```bash
bash /root/setup-vpn.sh --check
```

Если установка оборвалась, устраните указанную причину и продолжите:

```bash
bash /root/setup-vpn.sh --resume
```

Существующая 3x-ui, установленная другим способом, не перезаписывается. Скрипт рассчитан именно на пустой сервер. Продолжение использует сохранённые параметры и отметки завершённых этапов; не удаляйте `/etc/vpn-bootstrap`.

Если меняли порты или пути вручную после установки, встроенная проверка продолжит использовать исходные параметры и может сообщить ошибку. Это диагностический установщик, а не система постоянного управления конфигурацией.

Полезные команды:

```bash
systemctl status x-ui --no-pager
journalctl -u x-ui -n 50 --no-pager
ufw status numbered
systemctl list-timers vpn-cert-renew.timer --no-pager
journalctl -u vpn-cert-renew.service -n 50 --no-pager
tail -n 50 /etc/vpn-bootstrap/acme-install.log
```

Если сертификат не выдан, проверьте публичный IP, входящий TCP 80 в firewall провайдера и время сервера (`timedatectl status`). Затем используйте `--resume`. Установщик не переключается молча на незащищённую панель при ошибке HTTPS.

Если панель работает, а VPN нет, проверьте порт VPN у провайдера, Flow клиента, актуальность ссылки и доступность выбранного Target/SNI. Локальная проверка не может определить блокировку со стороны сети телефона.

Сертификат по IP короткоживущий. Установлен systemd-таймер, который проверяет продление дважды в сутки. Успешное продление перезапускает x-ui, что может кратковременно прервать соединения. Ключ сертификата, пароль панели и ключи Reality не публикуйте.

Для обновления панели предусмотрено штатное меню `x-ui`. Этот скрипт не является обновлятором: после обновления 3x-ui отдельно проверяйте совместимость и работоспособность VPN.
